# Decisions and trade-offs

| # | Decision | Alternatives considered | Why | Cost / risk accepted |
|---|---|---|---|---|
| D1 | **Lakeflow Declarative Pipeline (serverless) + Auto Loader** for ingestion | one-off CTAS loads (the original build), notebooks with plain Spark | declarative expectations and quarantine, incremental file discovery, event-log metrics as evidence | pipeline update time (~1.5 min) for a small dataset |
| D2 | **Pipeline feeds the existing governed gold tables** (publish task `INSERT OVERWRITE`) | let the pipeline own gold as materialized views (drop + recreate) | keeps certification, domain assignments, comments, Genie and metric-view links; no destructive drop of live tables | gold lineage passes through a job SQL step, not a pipeline flow |
| D3 | **One schema contract** (`evidence/contracts/gold_schemas.json`) generated from the live tables | hand-written schemas | the pipeline casts to exactly what metric views and Genie expect; `verify_live.py --contract` proves it (21/21) | contract must be regenerated if gold changes |
| D4 | **Classical ML** (gradient boosting + sigmoid calibration, out-of-time test with a 30-day embargo) for failure risk | LLM classification, anomaly score thresholds | calibrated probabilities, cheap, explainable (permutation importance, top driver), auditable | needs labelled failures; recall at 0.5 is about 49%, so the app alerts at 0.30 |
| D5 | **LLM (ai_query) only for the narrative brief**, grounded on a facts string from governed tables | free-form LLM over raw data | no invented numbers: the prompt only contains governed facts; EN + IT | brief quality depends on the model; marked "advice, not a decision" |
| D6 | **Lakebase as the app's serving + transactional store** | query the SQL warehouse from the app; external Postgres | millisecond reads, transactional write-back, a uniqueness constraint against duplicate escalations, managed by Databricks | needs a sync step (D7) |
| D7 | **pg8000 upsert sync job** Delta → Lakebase | managed synced tables | synced tables need a UC database catalog; this shared metastore denies CREATE CATALOG (`evidence/lakebase/synced_table_attempt.txt`) | custom code (idempotent, tested, ~1 min/run); swap for synced tables in a customer metastore |
| D8 | **Actions copied back to Delta** (`ops_launch_actions`) | Lakebase CDF / federation | CDF to the FEVM catalog bucket isn't available here; copy-back is simple and lets Genie and the dashboard see decisions | daily latency for Genie (the app itself is real time) |
| D9 | **Genie grounded on metric views**, plus ML/value/action tables | Genie on raw facts | one certified definition per KPI (e.g. OEE = A×P×Q), consistent with finance and the dashboard | metric views must be maintained as the business evolves |
| D10 | **Genie on behalf of the user** in the app | app service principal for everything | UC permissions per person; no broad data grants to the app | needs `user_api_scopes`; the app SP is the fallback |
| D11 | **Fictional names, deterministic generator (seed 42)**, real processes | public dataset | the storyline needs causal links (launch gates → revenue, wear → failure → supply); reproducible runs | not real-world distributions; value figures are estimates with editable assumptions |
| D12 | **Assumptions in a table, not in code** (`value_assumptions`) | constants in the notebook | business owners can challenge and edit them; every euro figure shows its formula | estimates, not measured savings (validate in a pilot) |
